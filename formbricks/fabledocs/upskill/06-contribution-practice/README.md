# 06 — Contribution Practice

The ladder from safe first PRs to architecture-level projects. Every item names its blast radius, the pattern it follows, its test plan, and what would make a maintainer reject it — plus a one-line "Interview story potential," because completed tickets are STAR stories in waiting ([08-interview-prep/06](../08-interview-prep/06-behavioral-star-stories.md)).

1. [01-good-first-tickets.md](01-good-first-tickets.md) — 18 junior tickets (hours each)
2. [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) — 12 cross-layer tickets (days each; design notes required first)
3. [03-senior-build-projects.md](03-senior-build-projects.md) — 6 projects (2 days–4 weeks)
4. [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) — 8 judgment exercises with self-grading

Working rules: branch always; smallest possible diff (CI checks PR size!); run lint + targeted tests before pushing; PR bodies per [07-career-and-collaboration/02](../07-career-and-collaboration/02-writing-prs-and-rfcs.md). If a ticket touches public API or SDK surface, write the proposal issue first.
