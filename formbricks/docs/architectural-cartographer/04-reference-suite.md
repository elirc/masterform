# Reference Suite

## Doc 1: Junior Onboarding Guide

Start by reading scripts and setup files: root commands (`package.json:18-31`), environment template (`.env.example:9-61`), setup script (`scripts/setup-dev-env.sh:126-161`), Docker services (`docker-compose.dev.yml:1-76`), and database scripts (`packages/database/package.json:36-44`). Then read the product entry shell (`apps/web/app/layout.tsx:24-43`) and authenticated app shell (`apps/web/app/(app)/layout.tsx:18-45`). Your first feature trace should be survey list because it uses route files, server page, client state, API route, auth, Prisma, and tests.

## Doc 2: Mid-Level Architecture Guide

The most common pattern is route-file delegation into modules. Example: the survey URL file re-exports `SurveysPage` (`apps/web/app/(app)/environments/[environmentId]/surveys/page.tsx:1-4`), and the actual page loads project/auth/locale data (`apps/web/modules/survey/list/page.tsx:23-59`). Client data lives in React Query for the survey list (`apps/web/modules/survey/list/hooks/use-surveys.ts:25-51`). Backend HTTP behavior lives in route handlers and wrapper libraries (`apps/web/app/api/v3/surveys/route.ts:20-82`, `apps/web/app/api/v3/lib/api-wrapper.ts:345-423`).

## Doc 3: Senior Ownership Guide

Own the boundaries. Do not let UI components perform authorization. Do not let API routes query unscoped data. Do not let database services return more fields than callers need. The codebase already demonstrates these boundaries through `getEnvironmentAuth` before rendering survey list props (`apps/web/modules/survey/list/page.tsx:28-39`), `requireV3WorkspaceAccess` before survey reads (`apps/web/app/api/v3/surveys/route.ts:36-48`), and `surveySelect` for minimal list fields (`apps/web/modules/survey/list/lib/survey-record.ts:5-22`).

## Doc 4: Code Review Guide

Review in this order:

1. Routing: is the URL file correct and does it delegate cleanly (`apps/web/app/(app)/environments/[environmentId]/surveys/page.tsx:1-4`)?
2. Auth: is session/API-key access checked through shared helpers (`apps/web/app/api/v3/lib/auth.ts:79-122`)?
3. Data scoping: does Prisma include `environmentId`, `organizationId`, or equivalent tenant boundary (`apps/web/modules/survey/list/lib/survey-page.ts:155-164`)?
4. Contract: are Zod schemas or response helpers updated (`apps/web/modules/survey/list/types/survey-overview.ts:1-39`, `apps/web/app/api/v3/lib/response.ts:136-173`)?
5. UI: is user-facing text translated and date formatting locale-aware (`apps/web/modules/survey/list/components/survey-card.tsx:31-45`, `apps/web/modules/survey/list/components/survey-card.tsx:82-87`)?
6. Tests: are route, service, hook, or E2E tests updated where the behavior changed (`apps/web/app/api/v3/surveys/route.test.ts:91-372`, `apps/web/modules/survey/list/lib/survey-page.test.ts:49-334`)?

## Doc 5: Debugging Guide

For a broken survey dashboard:

1. Confirm the route points to `SurveysPage` (`apps/web/app/(app)/environments/[environmentId]/surveys/page.tsx:1-4`).
2. Check server page failures: project lookup, billing redirect, environment auth, locale (`apps/web/modules/survey/list/page.tsx:23-59`).
3. Check local-storage filters and `enabled` state (`apps/web/modules/survey/list/components/survey-list.tsx:55-105`).
4. Inspect network request URL generated by `buildSurveyListSearchParams` (`apps/web/modules/survey/list/lib/v3-surveys-client.ts:38-79`).
5. Inspect API response shape and request id (`apps/web/app/api/v3/lib/response.ts:136-149`, `apps/web/app/api/v3/lib/api-wrapper.ts:233-246`).
6. Inspect database scoping and cursor query (`apps/web/modules/survey/list/lib/survey-page.ts:204-223`).

## Doc 6: Change Playbook

To add a survey list field:

1. Add it to Prisma select if it exists in DB (`apps/web/modules/survey/list/lib/survey-record.ts:5-22`).
2. Add it to the list item schema/type (`apps/web/modules/survey/list/types/survey-overview.ts:13-39`).
3. Ensure serializer exposes only public fields (`apps/web/app/api/v3/surveys/serializers.ts:11-18`).
4. Parse date/string differences in the API client if needed (`apps/web/modules/survey/list/lib/v3-surveys-client.ts:5-35`).
5. Render with `t()` and shared formatting helpers (`apps/web/modules/survey/list/components/survey-card.tsx:31-45`, `apps/web/modules/survey/list/components/survey-card.tsx:82-87`).
6. Update route/service/hook/E2E tests according to where behavior changed.

## Doc 7: Interview Walkthrough

"Formbricks is a survey platform implemented as a pnpm/Turbo monorepo. The main web app is Next.js App Router in `apps/web`; shared packages include Prisma database, types, surveys, storage, cache, and UI-adjacent packages (`package.json:5-33`, `apps/web/package.json:1-23`, `packages/database/package.json:1-31`). A core flow is the survey dashboard: the route file delegates to a module page, the server page loads auth/project/locale, the client component owns filters and React Query, the v3 API route authenticates by session or API key, resolves workspace access, reads cursor-paginated survey rows from Prisma, and returns a `{ data, meta }` envelope (`apps/web/app/(app)/environments/[environmentId]/surveys/page.tsx:1-4`, `apps/web/modules/survey/list/page.tsx:23-59`, `apps/web/modules/survey/list/hooks/use-surveys.ts:25-51`, `apps/web/app/api/v3/surveys/route.ts:20-82`, `apps/web/modules/survey/list/lib/survey-page.ts:412-440`)."
